# הון. — דגם לתוכנת הצהרות הון

פרויקט עצמאי של משרד עבדי בן גל, נפרד לחלוטין ממאגר `abady-crm`.

תכנית המעבר מהדגם למערכת מאובטחת: [docs/production-plan-he.md](docs/production-plan-he.md).
מיפוי טופס 1219 שסופק: [docs/form-1219-mapping-he.md](docs/form-1219-mapping-he.md).

## הפעלה

Node 24 ו־npm 11 נבדקו בסביבה.

```bash
npm ci --cache /tmp/abady-capital-npm-cache --no-audit --no-fund
npm run dev
```

שרת הפיתוח משתמש בפורט 5174. בדיקות: `npm test`; בנייה: `npm run build`.

## הדגם

תיק לדוגמה, איסוף מסמכים, הדמיית OCR ובדיקת ספרים, שורות הצהרה ניתנות לעריכה,
השוואת הון ומקורות/שימושים, דוח סוכן בדיקה, פורטל לקוח וטיוטות מייל/וואטסאפ
המחייבות אישור לפני הדמיית שליחה. עריכת הודעה או נתוני תיק מבטלת אישור קודם.

מסך הפתיחה הוא מרכז שליטה למשרד: רשימת לקוחות, שלב נוכחי, אחוז התקדמות,
מסמכים חסרים, אחראי, תאריך יעד ופעילות אחרונה. החיפוש והסינון פעילים.
תיק משפחת לוי פתוח לעריכה מלאה; חמש הרשומות האחרות הן נתוני מעקב לדוגמה.

הדגם שומר נתוני דוגמה ב־localStorage של הדפדפן ויכול להוריד גיבוי ונייר עבודה.
צירוף קובץ רושם שם קובץ בלבד. התוכן אינו נשמר, אינו נשלח ואינו עובר OCR אמיתי.
אין שליחת מייל/וואטסאפ, הגשה לרשות המסים או חיבור למסד נתונים בשלב זה.
מיפוי למהדורה העדכנית של טופס 1219 עדיין מחייב אימות.

## השוואת הון לפי דוגמת המשרד

במסך **השוואת הון**, לחצו **טעינת דוגמת המשרד** כדי לבדוק את הצילום המצורף:
רכוש נקי קודם 881,976; נוכחי 1,079,828; גידול 197,852;
שימושים 190,310; מקורות 529,789; יתרה למחיה ועודף זמני 141,627.
אומדן מחיה אפס הועתק מהצילום וטעון בדיקה. אין להסיק שלא היו הוצאות.

שימושים ומקורות ניתנים לעריכה לכל שנה. הסיכומים, יתרת המחיה ועודף/חוסר ההון
מתעדכנים יחד; מחיה היא שלב נפרד. הסוכן מסמן אומדן לא מאושר, היעדר אסמכתאות,
שיוך לשנה מחוץ לתקופה וסכומים ללא שיוך שנתי. שינוי בהשוואה מבטל אישור הודעה.
אפשר לייצא נייר עבודה שנתי ולהדפיסו.

דוגמת הצילום משתמשת בסיכומי הצהרות מיובאים **ללא פירוט נכסים**. היא אינה
מחליפה את שורות ההצהרה או מסמכי התיק. אפשר לבחור במפורש להשתמש בסיכומים
הנגזרים מפירוט ההצהרה. סכומים מהדגם הקודם נשמרים ללא חלוקה שנתית מומצאת.

## הפרדה מה־CRM

אין בפרויקט קוד CRM, מפתחות, חיבור Supabase או נתוני לקוחות אמיתיים.
יש ליצור פרויקט Supabase חדש ומבודד לתוכנת ההון; אין להשתמש בפרויקט ה־CRM.
לא הופעלו שינויים בסכמה או במידע של מסד ה־CRM.
את כתובת הפרויקט החדש ואת המפתח הציבורי יש להוסיף בעת מימוש החיבור בפועל.
אין להכניס מפתח `service_role` לקוד דפדפן או למאגר.
