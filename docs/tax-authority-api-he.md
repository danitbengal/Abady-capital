# התאמה לשידור הצהרת הון ב־API

## המקור והיקף ההתאמה

מסמך שסיפק המשרד: `תבנית אפיון API.pdf`, ‏87 עמודים פיזיים,
`CapitalDeclarationApi`, מהדורה `1.0 / 05.2025`.
SHA-256: `6cf9862fff1cba4336380b2dc547ead03ea62cc5f7e94147f2eacb120dc7a485`.
המסמך המקורי אינו מועתק למאגר ואינו משודר.

המסמך מפרט חמישה שירותים: Step1–Step4 ו־Full. ההתאמה הנוכחית משתמשת
**רק ב־CapitalDeclarationsFull**, לשידור כל חלקי ההצהרה יחד. היא אינה שולחת
את ארבעת השלבים ברצף: המפרט מזהיר שדיווח חוזר במצב טיוטה מוחק ומחליף
דיווח קודם; הצהרה שכבר הוגשה אינה ניתנת להגשה חוזרת.

שמות endpoints מועתקים מסעיף 1.5, עמוד פיזי 63:

- Sandbox: `https://ita-api.taxes.gov.il/shaam/tsandbox/capitalDeclarationsApi/v1/CapitalDeclarationsFull`
- Production: `https://openapi.taxes.gov.il/shaam/production/capitalDeclarationsApi/v1/CapitalDeclarationsFull`

אין שדות להשוואת הון, הערות עבודה, מסמכי PDF, בני משפחה או חבילת חתימה
בבקשה הזו. הם **אינם** נוספים לגוף השידור. לא הומצא שירות API לצירופם.
גם `note`, ‏`officeNote`, ‏`officeNotes`, ‏`documentId`, תוצאות OCR ותוכן קבצים אינם משודרים.

## ההתאמות בקוד

- `src/tax-api/schema.ts`: רשימת שדות מותרת מלאה ל־Full, כולל עסקים וכספות.
- `payload.ts`: יצירת טיוטה מנתוני 1219, תאריכי UTC, סינון שדות, בדיקות
  מספרים ותאריכים, רשימות סגורות, פירוט אחר, מטבע זר, כפילות רישוי,
  התאמת סכומים למקור וטביעת SHA-256 לתוכן שאושר.
- `TaxApiPanel.tsx`: השלמות ואישור לייצוא בקשת Sandbox בדגם. אינו מבצע שידור.
- `CaseTaxApiPanel.tsx`: בסביבת המערכת המחוברת, שמירה/אישור/שידור והיסטוריה
  למנהלת ולרואה חשבון מורשה בלבד. עובד או מנהלת חשבונות אינם מורשים לשדר.
- `transport.ts`: קריאת שרת אחת לכתובת מוגדרת מראש, OAuth2 Bearer,
  חסימת ייצור נפרדת, בדיקת hash ותוצאה מפורשת `isSuccess: true`.
- מיגרציה `20261028000100_tax_api_submissions.sql`: רשומות שידור, RLS,
  אישור תוכן בלתי ניתן לעריכה, מניעת ניסיון כפול, בדיקת שינוי תיק לאחר
  אישור ויומן ביקורת ללא תוכן פיננסי.
- Edge Function ‏`tax-api`: אימות משתמש והרשאה, ולידציה חוזרת בשרת,
  אישור ולכידת בקשה לשידור באופן אטומי. סודות קיימים רק בשרת.

## תהליך ההפעלה

1. מריצים **רק את המיגרציה החדשה** אחרי מיגרציית הליבה שכבר נוצרה. אין צורך
   להריץ שוב את מיגרציית הליבה או למחוק נתונים.
2. פורסים את `tax-api` ב־Supabase CLI עם אימות JWT מופעל; אין להשתמש ב־`--no-verify-jwt`.
3. מגדירים בשרת `TAX_API_ALLOWED_ORIGINS` ככתובות origin מלאות ומדויקות של
   האתר, מופרדות בפסיק. אין להשתמש ב־`*`.
4. משלימים רישום בית תוכנה/מייצג והרשאות שירות מול רשות המסים. המסמך
   מפנה למדריך OAuth2 נפרד ואינו מספק פרטי רישום, scopes, הנפקת token
   או תהליך refresh. אין לממש grant או להמציא endpoints מעבר למסמך.
5. מזינים token Sandbox תקף בכספת הסודות של Edge בשם
   `TAX_API_SANDBOX_ACCESS_TOKEN`. לאחר אימות הרשאות וחוזה Swagger העדכני,
   מגדירים `TAX_API_ENABLE_SANDBOX=true`. ה־token חייב להתחדש מחוץ למימוש
   הראשוני לפני פקיעתו; אין כיום מנהל refresh אוטומטי.
6. פותחים תיק עם מספר נישום ותאריך תואמים, משלימים בקשה, שומרים אותה,
   מאשרים ואז מבצעים בדיקה יזומה אחת. נתוני Sandbox מאושרים נדרשים מהרשות;
   אין לשלוח נתוני לקוח אמיתי לשם בדיקה.
7. רק אחרי בדיקות קבלה מול הרשות מגדירים בנפרד
   `TAX_API_PRODUCTION_ACCESS_TOKEN` ו־`TAX_API_ENABLE_PRODUCTION=true`.
   אישור תוכן ואישור פעולת השידור עדיין נדרשים בממשק.

בברירת המחדל **שתי סביבות השידור כבויות**. המיגרציה והפונקציה לא נפרסו
לפרויקט המרוחק במסגרת השינוי; לא התקבלה הרשאת OAuth2 ולא בוצע שידור לרשות.

## תוצאות, דיוק ונקודות להכרעה בבדיקות Sandbox

- `200` עם `isSuccess: true` מציין הצלחת שירות; תשובת Sandbox אינה קבלה
  על הגשה בייצור. המסמך מחזיר `rcText` ולא מציג מספר אסמכתת הגשה; אין להמציא
  מספר קבלה או להציג שההצהרה הוגשה סופית על סמך מספר רשומה מקומי.
- שגיאת 400/401/403/406/422 נשמרת כדחייה; 5xx, גוף לא מזוהה, JSON לא תקין
  או ניתוק מסומנים `unknown`. אין retry אוטומטי. גם ניסיון `sending`
  שנותר לאחר נפילת שרת דורש בירור ידני ולא לכידה מחדש. אין כאן עדיין שירות
  של הרשות לבדיקת סטטוס או פתיחה מחדש של ניסיון לא ודאי.
- התוצאה הנחזית בסביבה המקומית/ב־mock אינה אימות של ממשק הרשות החי.
- מופיעים במסמך הבדלי אותיות גדולות/קטנות ושגיאות העתקה בטבלאות. השמות
  נלקחו מדוגמת Full בעמודים 66–76, אך חובה לאמת מול Swagger שהרשות מספקת.
  `POST` הוא אופן הקריאה שהוכן במתאם; הטבלה ב־PDF אינה מציינת verb מפורש,
  ויש לאמת זאת לפני הפעלת סביבת Sandbox.
- בקודי בנק/סניף/מדינה/כתובת אין נתוני רשימה חתומים במסמך. הממשק דורש
  בדיקה ידנית מול המקורות הרשמיים; הוא אינו טוען שקוד מספרי הוא קוד קיים.
- ב־PDF שמות קישורי הבנקים והסניפים נראים מוחלפים. אין לטעון אותם אוטומטית
  לפי הכותרת בלי אימות.
- המפרט מציין `costILS > 1`, בעוד טופס ההון דורש לעיתים ערך 1 למתנות וירושות.
  כרגע סכום כזה נחסם לשידור עד הבהרה מול הרשות; אין להגדילו אוטומטית.
- סוג LONG תומך ב־19 ספרות, אך מספר JS בטוח מוגבל ל־`2^53-1`.
  ערכים גדולים יותר נחסמים במקום לעגל. אין תמיכה ב־LONG מלא עד לחוזה
  מאומת ומקודד JSON מדויק תואם.
- אחוזי החזקה מוגבלים ל־0–100 עם שתי ספרות עשרוניות; טבלאות המסמך אינן
  עקביות במספר הספרות שלפני הנקודה. יש לבדוק החזקה של 100 ב־Sandbox.
- התאמת הסכומים המקומית היא בקרה משלימה ואינה חישוב של הרשות. טיפול בעלויות
  נוספות בנכס, מניות שטרם הוקצו וקיבוץ עסק עצמאי/שותפות מחייב בדיקה מקצועית
  מול הנתונים והכללים המעודכנים. אין להחליף בדיקה זו באישור אוטומטי.

## בדיקות

`npm test` כולל בדיקות חוזה/דליפת הערות/דיוק מספרים/שינוי מקור, ולידציית
מטבע/תאריכים/כספת, מצב בדיקות מול ייצור, hash ואי־חזרה לאחר ניתוק. בדיקות
PostgreSQL מריצות את שתי המיגרציות ובודקות הרשאות, מצב אישור, מניעת כפילות,
חסימת שליחה נוספת במצב לא ידוע ושינוי תאריך לאחר אישור. כל בדיקות התקשורת
נעשות מול mocks; לא נשלחת בקשה לרשות המסים בבדיקות.

בדיקת Edge נוספת (נבדקה עם Deno ‏2.5.6):

```bash
deno test --no-config --node-modules-dir=manual --allow-env supabase/functions/tax-api/handler_test.ts
```

לבדיקה זו אין הרשאת רשת; היא מחליפה את fetch ב־mock ובודקת חסימת origin,
משתמש לא מחובר, שידור כבוי, ניסיון כפול ושמירת תוצאה מפורשת אחת.
