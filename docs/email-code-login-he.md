# כניסה בקוד חד־פעמי במייל

מסך `?mode=secure` שולח קוד דרך Supabase Auth ומאמת אותו באמצעות `verifyOtp`.
נשלחות בקשות עבור משתמש קיים בלבד (`shouldCreateUser: false`); הכניסה אינה
יוצרת משתמש חדש ואינה מעניקה הרשאות משרד או לקוח. הרשאות RLS חלות לאחר הכניסה.

## הגדרה בפרויקט ההון

ב־Supabase פותחים Authentication → Email Templates → Magic Link.
יש לשמור תבנית הכוללת את `{{ .Token }}` כדי לקבל קוד במייל ולא רק קישור.
לדוגמה:

```html
<div dir="rtl">
  <h2>קוד כניסה למערכת הצהרות הון</h2>
  <p>קוד הכניסה החד־פעמי שלך:</p>
  <p dir="ltr" style="font-size:28px;font-weight:bold">{{ .Token }}</p>
  <p>אם לא ביקשת כניסה, אפשר להתעלם מההודעה.</p>
</div>
```

הגדרת התבנית ומשלוח המייל בפועל מחייבים גישת ניהול לפרויקט וספק מייל תקין.
ספק המייל המובנה של Supabase מוגבל בנמענים ובקצב; עבור עובדי המשרד יש להגדיר
SMTP מתאים. לא שומרים סודות SMTP בקוד דפדפן.

הקוד מוגבל בזמן לפי הגדרות Auth בפרויקט. הממשק ממתין 60 שניות לפני שליחה חוזרת;
Supabase אוכף את מגבלות המשלוח והאימות בצד השרת. אין לכתוב קודים או סיסמאות ללוג.
כניסה במייל בלבד אינה תחליף ל־MFA שנדרש לפני שימוש בנתוני לקוחות אמיתיים.
